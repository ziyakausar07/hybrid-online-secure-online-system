The Hybrid Secure Voting System is a web-based college election platform designed to replace paper-based or manual voting processes with a secure, transparent, and real-time digital alternative.

The system follows a hybrid architecture — a React single-page application talks to a Node.js Express gateway which handles authentication, session management, and rate-limiting, then proxies sensitive operations to a Java Servlet (Tomcat) backend that owns the core business logic. MySQL is the shared data store for users, elections, candidates, votes, and nomination forms.

Real-time vote tallying is broadcast to all connected clients via Socket.IO, while OTP-based email verification and JWT tokens ensure only authenticated, eligible voters can cast a ballot — and only once.

Key Features

Core capabilities of the platform

📲
OTP-Based Voter Verification
Before casting a ballot, voters receive a one-time password on their registered email. GenerateOTPServlet and VerifyOTPServlet ensure only the rightful account holder can vote — preventing proxy voting and impersonation.
🔐
JWT Auth and Role-Based Access
Every API request requires a valid JWT. Roles (admin / voter) control access — admins can create elections and view nominations; voters can only vote and view results after casting their ballot.
📡
Real-Time Live Results
Vote tallies stream live to all connected browsers via Socket.IO WebSockets. A Recharts bar chart updates in real time — no refresh needed. Results are gated: only users who have already voted can see them.
🗳️
Single-Vote Enforcement
The system checks the votes table before allowing submission. Once a user has voted, all subsequent vote attempts are rejected at the Node gateway — ensuring one-person-one-vote integrity at every layer.
🗂️
Election Management
Admins create elections with title, description, start/end dates, and voting window duration. Elections auto-expire. Candidates are linked per election via FK constraints, and a nomination form lets students apply to stand.
🏫
College Profile Management
Voters complete a rich profile — USN, branch, semester, division, department, college email — used to validate eligibility and displayed on the candidate nomination form. Admins can update college info centrally.
💬
In-App Messaging System
Admins broadcast messages to voters via GetMessagesServlet. Voters receive and read message threads in the dashboard — keeping all election communications inside the platform with no need for external email.
🛡️
Multi-Layer Security
Helmet enforces strict HTTP headers. Rate limiter blocks abuse (100 req / 15 min). Sessions expire in 15 minutes. Passwords are bcrypt-hashed. CORS allows only whitelisted origins. JSON body size capped at 10 KB.
